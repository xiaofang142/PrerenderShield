## 常见问题

### 服务启动失败

**症状**: 服务无法启动或启动后立即退出

**可能原因及解决方案**:
1. **Redis连接失败**
   - 检查Redis服务是否运行: `redis-cli ping`
   - 检查配置文件中的Redis连接信息
   - 确认Redis端口未被防火墙阻挡

2. **端口被占用**
   - 检查API端口(默认9598)和控制台端口(默认9597)是否被占用
   - 使用 `lsof -i :<port>` 查看端口占用情况
   - 修改配置文件中的端口号

3. **配置文件错误**
   - 验证YAML格式是否正确
   - 检查必填字段是否完整
   - 确认路径是否存在

### 站点服务无法访问

**症状**: 站点配置正确但无法通过浏览器访问

**排查步骤**:
1. 检查站点服务器是否成功启动
   - 查看日志中是否有 "站点服务器启动成功" 的信息
   - 确认站点配置的端口是否正确

2. 检查静态文件路径
   - 确认 `static_dir` 配置的路径存在
   - 检查站点对应目录下是否有 `index.html` 文件

3. 检查域名配置
   - 确认请求的域名与站点配置中的域名匹配
   - 检查hosts文件或DNS解析是否正确

### 渲染预热功能异常

**症状**: 爬虫请求无法正确渲染或返回错误

**可能原因**:
1. **Chromium未安装或路径错误**
   - 确认已安装Chrome或Chromium
   - 检查浏览器路径配置

2. **渲染超时**
   - 增加 `timeout` 配置值
   - 检查目标页面加载时间

3. **内存不足**
   - 减少浏览器池大小 (`pool_size`)
   - 增加系统内存或启用交换分区

## 性能问题

### 高内存使用

**诊断方法**:
- 使用 `top` 或 `htop` 监控内存使用
- 检查渲染引擎池大小配置
- 查看是否有内存泄漏

**解决方案**:
- 调整 `pool_size` 和 `max_pool_size` 参数
- 增加 `idle_timeout` 以更快释放空闲浏览器实例
- 定期重启服务释放内存

### 高CPU使用

**可能原因**:
- 并发请求过多
- 渲染复杂页面
- 防火墙规则过多或复杂

**优化措施**:
- 限制并发连接数
- 优化防火墙规则，减少不必要的检查
- 使用CDN减轻服务器压力

### 响应时间长

**排查要点**:
- 检查网络延迟
- 验证目标页面加载速度
- 检查缓存命中率

## 安全相关问题

### 防火墙规则不生效

**检查步骤**:
1. 确认防火墙功能已启用 (`enabled: true`)
2. 验证规则格式是否正确
3. 检查规则优先级顺序

### IP黑名单/白名单无效

**排查方法**:
- 确认IP地址格式正确
- 检查黑白名单优先级（白名单优先级更高）
- 验证配置是否已正确应用

### 认证失败

**常见原因**:
- 用户名或密码错误
- JWT令牌过期
- 时间同步问题导致的令牌验证失败

## 配置问题

### 配置热更新不生效

**解决步骤**:
1. 检查配置文件格式是否正确
2. 确认配置变更事件是否正确发布到Redis
3. 查看日志中是否有配置加载错误信息

### Redis配置同步问题

**排查方法**:
- 检查Redis连接状态
- 验证配置键是否存在
- 确认Redis权限设置

## 日志分析

### 日志级别说明
- **DEBUG**: 详细调试信息
- **INFO**: 一般信息性消息
- **WARN**: 警告信息，需要注意
- **ERROR**: 错误信息，需要处理
- **FATAL**: 致命错误，服务可能停止

### 重要日志标识

**启动相关**:
- "Server started successfully" - 服务启动成功
- "站点服务器启动成功" - 站点服务启动成功
- "Redis subscriber started" - Redis订阅启动

**错误相关**:
- "Failed to start" - 启动失败
- "Connection refused" - 连接被拒绝
- "Permission denied" - 权限不足

**性能相关**:
- "Rendering took X ms" - 渲染耗时
- "Cache hit rate: X%" - 缓存命中率
- "Active browsers: X" - 活跃浏览器数量

### 日志路径
- 主日志: `data/prerender-shield.log`
- 访问日志: `logs/access.log` (如果启用)
- 错误日志: `logs/error.log` (如果启用)

## 监控指标

### 关键性能指标

**响应时间**:
- 平均响应时间应小于500ms
- 95%请求应在2秒内完成

**吞吐量**:
- 监控每秒请求数(RPS)
- 检查并发连接数

**资源使用**:
- CPU使用率应低于80%
- 内存使用率应低于85%

### 健康检查

定期执行健康检查:
```bash
curl http://localhost:9598/api/v1/health
```

关注返回的健康详情，特别是:
- Redis连接状态
- 内存使用情况
- Goroutine数量

### Prometheus指标

如果启用了Prometheus监控，以下指标值得关注:
- `prerender_requests_total` - 总请求数
- `prerender_response_time_seconds` - 响应时间
- `prerender_cache_hits_total` - 缓存命中数
- `prerender_blocked_requests_total` - 阻挡请求数

## 诊断命令

### 检查服务状态
```bash
# 检查端口占用
lsof -i :9598 :9597 :8080-8090

# 检查进程
ps aux | grep prerender

# 检查Redis连接
redis-cli ping
```

### 验证配置
```bash
# 验证YAML格式
yamllint config.yml

# 检查配置文件语法
./api --config config.yml --dry-run  # 如果支持
```

### 测试API
```bash
# 健康检查
curl -s http://localhost:9598/api/v1/health | jq

# 获取站点列表
curl -H "Authorization: Bearer $TOKEN" http://localhost:9598/api/v1/sites
```

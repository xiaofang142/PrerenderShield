## 二、六大业务场景流程

### 场景1：普通用户访问网站

```
用户浏览器 → DNS解析到Prerender Shield
  → 站点服务器 (端口8081) 
    → [中间件] JWT认证? (否, 透传)
    → [中间件] WAF检测 (通过)
    → 爬虫识别? (否, 普通浏览器UA)
    → 反向代理 → 源站服务器
    → 源站返回动态页面 → 代理返回给用户
```

**涉及模块**: `site-handler` → `middleware/waf` → `crawler/detector` → `proxy` → 源站

### 场景2：搜索引擎爬虫抓取

```
Googlebot → 站点服务器
  → [中间件] WAF检测 (通过, 爬虫列入白名单)
  → 爬虫识别? (是, Googlebot)
  → 预渲染引擎入口
    → 检查Redis缓存 ? 命中 → 直接返回
    → 缓存未命中:
      → 渲染队列排队 (Priority: Normal)
      → Chromium实例池分配实例
      → Headless Chromium 渲染页面
      → 返回完整HTML
      → 写入Redis

**涉及模块**: `crawler/detector` → `prerender/engine` → `cache/manager` → `prerender/pool/pool` → `prerender/queue`

### 场景3：攻击请求被拦截

```
攻击者 (SQL注入尝试) → 站点服务器
  → [中间件] WAF检测
    → 检测器链执行:
      1. UA检测 (通过)
      2. IP黑名单 (未命中)
      3. IP白名单 (未命中)
      4. 速率限制 (未触发)
      5. GeoIP (通过)
      6. 请求头检测 (通过)
      7. 请求方法检测 (通过)
      8. URL路径检测 (通过)
      9. 文件完整性 (通过)
      10. 爬虫行为 (通过)
      11. 异常流量 (通过)
      12. 自定义规则 → SQL注入模式匹配! →
    → 规则评分: 95 (高风险)
    → 动作: Block
  → 返回 403 Forbidden
  → 记录攻击日志到Redis
  → (可选) Webhook告警
```

**涉及模块**: `firewall/engine` → `firewall/detectors/*` → `firewall/action` → `logging` → `monitoring/alerting`

### 场景4：管理员操作 (预热触发)

```
管理员 → 管理控制台 (:9597)
  → 登录 (JWT认证)
  → 点击"一键预热"
  → API请求: POST /api/v1/preheat/trigger { siteId, urls }
  → sites_controller 接收请求
  → 解析Sitemap或使用指定URL列表
  → 生成预热任务 → 加入渲染队列
  → 渲染引擎批量执行
  → 缓存结果
  → 返回预热状态
```

**涉及模块**: `controllers/preheat_controller` → `prerender/preheat` → `prerender/queue` → `prerender/engine` → `prerender/cache`

### 场景5：SSL证书自动续签

```
定时器触发 (每24小时)
  → ssl/auto_renewer.checkAndRenew()
  → acmeClient.ListCertificates() 获取所有证书
  → 遍历每个证书, 检查 expires_in
  → 如果 <=30天:
    → 执行 RenewCertificate(domain)
    → LEGO库通过ACME协议续签
    → 保存新证书到文件
    → 记录续签成功到Redis
    → 发送Webhook通知
  → 如果失败, 重试(MaxRetries次)
  → 全部失败 → Webhook告警
```

**涉及模块**: `ssl/auto_renew` → `ssl/acme_client` → `ssl/http_challenge|dns_challenge` → `redis` → webhook

### 场景6：零信任设备验证

```
高风险请求 → 站点服务器
  → WAF检测Allow (但评分较高)
  → 零信任模块介入:
    1. 设备指纹采集 (UA/屏幕/时区/字体等)
    2. 风险评分计算
    3. 如果评分 > 阈值:
      → 设备验证挑战
      → 验证通过 → 放行 + 记录信任
      → 验证失败 → 拦截
```

**涉及模块**: `security/zerotrust/device` → `security/zerotrust/continuous` → `security/botmanager/challenge`

## 三、配置管理业务流

```
┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│  管理员       │    │  管理API     │    │  ConfigManager│
│  修改配置     │───→│  更新配置    │───→│  配置验证     │
└──────────────┘    └──────────────┘    └──────┬───────┘
                                               │
                            ┌──────────────────┴──────────────────┐
                            │             验证通过?                 │
                            └──────┬───────────┬──────────┬───────┘
                                   │           │          │
                              是(YAML)    是(Redis)    否(回滚)
                                   │           │          │
                                   ▼           ▼          ▼
                            ┌──────────┐ ┌──────────┐ ┌──────────┐
                            │写配置文件 │ │写Redis   │ │返回错误  │
                            │+发送SIGHUP│ │发布订阅   │ │+旧配置   │
                            └────┬─────┘ └────┬─────┘ └──────────┘
                                 │             │
                                 ▼             ▼
                          ┌────────────┐ ┌────────────┐
                          │各服务热加载  │ │各服务订阅   │
                          │新配置       │ │同步更新    │
                          └────────────┘ └────────────┘
```

## 四、定时任务调度

| 任务 | Cron | 模块 | 说明 |
|------|------|------|------|
| SSL证书检查 | 每24h | `scheduler` → `ssl/auto_renew` | 检查证书即将过期 |
| 缓存清理 | 每小时 | `scheduler` → `cache` | 清理过期缓存 |
| 日志归档 | 每天 | `scheduler` → `logging` | 日志文件轮转 |
| 健康检查 | 每30s | `monitor` → `health_checker` | 系统自检 |
| Sitemap预热 | 可配置 | `scheduler` → `preheat` | 定期缓存预热 |
